# ADR-0001 — Scope of v0.1: verification first

- **Status:** Accepted
- **Date:** 2026-11-07

## Context

The original specification lists 22 deliverables and 11 detector categories. Much of the static
side overlaps existing tools: ruff `DTZ` (naive datetimes), ruff `S` / bandit (subprocess and shell),
pytest-socket (network), pytest-randomly (test order), time-machine / freezegun (clock),
pytest-env / `monkeypatch` (environment). A tool that mostly re-implements lint rules has little
reason to exist.

What no common tool does: **re-run a test under a changed environment and report, with evidence,
that it breaks.** That is AssumptionRadar's differentiator.

## Decision

v0.1 ships:

- Controlled verification engine (child-process re-runs of selected pytest tests) with scenarios
  `cwd`, `tz`, `encoding`, `env-unset:<NAME>`, `tmpdir`, and `locale` where supported (see Spike 0001).
- Runtime observation via audit hooks (ADR-0002).
- pytest plugin, JSON report (versioned schema), terminal report, minimal CLI.
- Stable diagnostic model and fingerprints (ADR-0004).

Deferred to v0.2+: static scanner, SARIF, baselines, suppressions, configuration file,
detector plugins, test-order investigation, container isolation, xdist support for observation.

Static rules will only be added where they are *not* already covered by ruff; the docs will
recommend ruff for those cases instead of duplicating them.

## Consequences

- An early, narrow release that can be validated on real projects.
- Users who only want lint-style warnings are pointed to ruff.
- The full specification is still the long-term target; ROADMAP.md tracks it.
